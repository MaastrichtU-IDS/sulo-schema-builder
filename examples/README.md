# Example schema artefacts

This folder holds the schema artefacts referenced in the paper's *Data Availability*
statement. Each artefact is generated by the SULO Schema Builder from a single schema model
(`schema.json`) — they are the exact outputs of the tool's export tabs and consistency check.

## Clinical Health Record (`clinical-health-record/`)

The case-study schema (loadable in the app via **Load Example**): **32 classes, 41 properties**,
aligned to SULO (30 classes) and SNOMED CT (2 classes). HermiT reports it **consistent and
coherent** (no unsatisfiable classes).

| File | Description |
|------|-------------|
| `schema.json` | The schema model (classes, properties, SULO mappings, mapping patterns) — the single source the artefacts below are generated from. |
| `clinical-health-record.rdfs.ttl` | Plain RDF Schema (RDFS) vocabulary. |
| `clinical-health-record.owl.ttl` | **OWL DL** ontology with SULO-compliant `owl:equivalentClass` restrictions (`owl:imports` SULO). This is the artefact the consistency check reasons over. |
| `clinical-health-record.shacl.ttl` | SHACL node shapes and property constraints. |
| `clinical-health-record.uml.mmd` | Mermaid `classDiagram` (UML) rendering. |

### Reproducing / checking

The OWL artefact can be checked for consistency with any OWL DL reasoner, e.g. via ROBOT + HermiT:

```bash
robot merge --input clinical-health-record/clinical-health-record.owl.ttl \
            --input https://w3id.org/sulo/sulo.ttl \
      reason --reasoner HermiT
```

No new experimental (patient) data were generated; these are schema artefacts only.
